# yps-wasm — песочница YoptaScript в браузере

Крейт собирает лексер, парсер и интерпретатор в WebAssembly и экспортирует одну функцию:

```ts
run_yopta(code: string): string  // бросает строку-диагностику при ошибке
```

Вывод `сказать` и `сказать.*` перехватывается через `OutputSink` из `yps-interpreter`
(`BufferSink`) и возвращается строкой, а не пишется в stdout.

## Сборка

```bash
cd crates/yps-wasm
npx --yes wasm-pack build --target web --out-dir www/pkg
```

`www/pkg/` — артефакт сборки, в git не попадает.

## Локальный запуск

```bash
python3 -m http.server 8000 --directory crates/yps-wasm/www
# затем открыть http://localhost:8000/
```

## Что не работает в браузере

Проверено на `wasm32-unknown-unknown`:

- `ФС` и `Сеть` — ловимая ошибка времени выполнения («operation not supported on this
  platform»), а не падение;
- `Процесс.переменные` пуст, `Процесс.рабочаяПапка` — пустая строка;
- `сказать.время`/`сказать.времяСтоп` — ловимая ошибка времени выполнения («недоступен в
  браузере»), а не падение;
- системные часы иначе не поддерживаются: `Дата.сейчас()` и таймеры (`чутка`, `интервал`)
  паникуют, вызов прерывается JS-исключением и страница показывает его в панели вывода;
  модуль после этого остаётся работоспособным. `захуярить Дата(мс)` работает;
- глубокая рекурсия упирается в стек JS раньше `MAX_CALL_DEPTH`;
- бесконечный цикл вешает вкладку: выполнение синхронное, воркера нет.

## Развёртывание

Публикация страницы (хостинг, GitHub Pages, домен) — отдельное решение и в этот крейт
не входит. Здесь только локально проверяемый артефакт.
